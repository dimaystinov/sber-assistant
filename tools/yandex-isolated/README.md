# Яндекс.Браузер в изолированном контейнере

Linux-сборка Яндекс.Браузера 26.10.0.1882 из [официального репозитория](https://repo.yandex.ru/yandex-browser/deb/). Браузер находится во внутренней сети Docker **без прямого выхода в интернет** и без монтирования файлов Mac или Docker-сокета. Отдельный прокси `yandex-egress` открывает обычные сайты через HTTP/HTTPS и блокирует доступ к локальным адресам и доменам Яндекса, перечисленным в `squid.conf`. Пользователь внутри контейнера непривилегированный. Профиль живёт в `tmpfs` и исчезает при остановке. Экран доступен через VNC на loopback-адресе контейнера; локальный мост использует `docker exec`.

Внутренний sandbox Chromium несовместим с используемыми ограничениями Docker Desktop на Apple Silicon; в этой конфигурации браузер запускается с `--no-sandbox`. Изоляцию обеспечивают границы контейнера, отсутствие прямого интернет-маршрута, привилегий и файловых монтирований. Это не эквивалент встроенной песочницы Chromium.

Образ собирается с сетью для загрузки Debian-пакетов и официального `.deb`. Версия и SHA256 пакета зафиксированы. Скрипты установки пакета не выполняются. После запуска браузер может обращаться к произвольным публичным сайтам через прокси. **Полностью исключить телеметрию при таком доступе нельзя**: список блокируемых доменов неполный, а HTTPS-запросы к разрешённым доменам прокси не расшифровывает. Для обновления пересоберите образ и проверьте новую версию и SHA256.

Для сайтов Сбера в образ добавлен корневой сертификат НУЦ Минцифры из официального источника, как указано в [инструкции Сбера](https://developers.sber.ru/help/certificates/how-to). Доверие к этому УЦ включено только внутри контейнера, системное хранилище Mac не менялось. Отпечаток SHA-256: `D2:6D:2D:02:31:B7:C3:9F:92:CC:73:85:12:BA:54:10:35:19:E4:40:5D:68:B5:BD:70:3E:97:88:CA:8E:CF:31`.

Запуск: `./run.sh`. Остановка: `./stop.sh`. Для просмотра можно подключиться VNC-клиентом к `127.0.0.1:5909`; доступ к этому порту есть только на самом Mac. Локальный участок VNC не шифруется. Учётные данные вводите только лично в открытой форме Сбера и не передавайте их ассистенту.

Локальный пароль VNC создаётся в `vnc-password.txt` с правами `0600`, не попадает в образ и не должен попадать в Git. Порт VNC привязан к `127.0.0.1` Mac. Сам браузер в контейнере не имеет монтирования этой папки.

## Доступ к песочнице Sber API

**Текущий статус:** форма входа СберБизнес открыта, но у пользователя нет учётной записи СберБизнес. Получить сертификат и токен из кабинета без авторизованной организации нельзя. [Официальные условия доступа](https://developers.sber.ru/docs/ru/sber-api/start/lk): действующий договор банковского обслуживания и заявление о присоединении к Sber API. Если организация уже подключена, администратор может выдать роль [«Разработчик Sber API»](https://developers.sber.ru/docs/ru/sber-api/start/personal-area). Для чемпионата можно запросить у организаторов выделенный тестовый доступ. Локальный симулятор не является официальной песочницей.

1. Откройте [официальную страницу входа СберБизнес](https://sbi.sberbank.ru:9443/) в контейнерном браузере и войдите с учётной записью организации. Доступ к личному кабинету Sber API зависит от роли пользователя в СберБизнес.
2. В меню «Все продукты и услуги» найдите «Сбербанк API» → «Sber API». Если сервис ещё не подключён, его подключение требует заявления и подписи уполномоченного лица организации. [Инструкция Сбера](https://developers.sber.ru/docs/ru/sber-api/start/connect).
3. Выберите сервис → вкладка «Песочница API» → «Перейти к настройке». В кабинете выпускаются тестовый TLS-сертификат `.p12` и токен доступа; они необходимы для API-запросов. [Описание песочницы](https://developers.sber.ru/docs/ru/sber-api/start/sandbox).

Профиль и загрузки контейнера временные. До остановки браузера экспортируйте выданный сертификат в защищённое хранилище через [`assistant/sber_cert_export.py`](../../assistant/sber_cert_export.py); [порядок получения доступа и проверки](../../docs/SBER-OFFICIAL-SANDBOX.md#план-на-11-ноября-что-получить-и-что-проверить). Не добавляйте `.p12`, пароль или токен в Git, README и логи. Для входа в СберБизнес прокси разрешает порт `9443` только адресу `sbi.sberbank.ru`; остальные нестандартные порты закрыты.

Проверка ограничений: `./verify.sh`. Она проверяет конфигурацию Docker, отсутствие прямого внешнего маршрута и недоступность тестового интернет-адреса без прокси. Если проверка не проходит, `run.sh` не должен считаться безопасным запуском.
