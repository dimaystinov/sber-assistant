# Подключение к официальной песочнице Sber API MCP

**Статус 10 ноября 2026:** транспорт реализован, локальный MCP handshake проверен. Официальный сайт и форму входа СберБизнес открыли в изолированном Яндекс.Браузере; соединение HTTPS проверено. У пользователя **нет доступа к СберБизнес**, а значит пока нет доступа к личному кабинету Sber API, тестовому сертификату и токену. Соединение с банковским стендом и фактические схемы tools **не проверены**. Ключ GigaChat не является токеном Sber API.

По [условиям личного кабинета Sber API](https://developers.sber.ru/docs/ru/sber-api/start/lk) необходимы действующий договор банковского обслуживания организации со Сбером и подписанное заявление о присоединении к Sber API. Сам по себе открытый сайт или личный аккаунт GigaChat этого доступа не создаёт. Если организация уже работает в СберБизнес, её уполномоченный администратор может оформить пользователю роль «Разработчик Sber API»; [инструкция Сбера](https://developers.sber.ru/docs/ru/sber-api/start/personal-area) указывает, что эта роль даёт доступ только к кабинету API, включая настройки песочницы. Если такой организации нет, нужен официальный доступ через организацию или предоставленные организаторами чемпионата тестовые реквизиты. Не следует выдавать локальную симуляцию за проверку банковского стенда.

Текст запроса администратору организации или организаторам чемпионата:

> Для тестирования кейса с MCP Sber API нужен доступ к песочнице набора «Компаниям». Просим предоставить доступ к личному кабинету Sber API с ролью «Разработчик Sber API» либо официальные тестовые параметры для выделенного сервиса: client_id, TLS-сертификат `.p12`, пароль к нему и access token со scope `MCP_COMMON` и scope выбранного MCP-инструмента. Передачу секретов просим организовать через защищённый канал, не через чат или репозиторий.

## План на 11 ноября: что получить и что проверить

1. Уточнить у организаторов чемпионата, выдаётся ли **официальная тестовая организация/учётная запись Sber API**. Если нет, попросить уполномоченного администратора организации с действующим СберБизнес и оформленным присоединением к Sber API выдать роль «Разработчик Sber API». Личный GigaChat-ключ для этого не подходит.
2. В [кабинете Sber API](https://developers.sber.ru/docs/ru/sber-api/start/connect) выбрать набор «Компаниям», создать или выбрать сервис и записать его `client_id` **без публикации секретов**. Включить для первого пробного сервиса scope `MCP_COMMON` и `MCP_CLIENT_INFO`.
3. В разделе «Песочница API» выпустить тестовый клиентский `.p12`, сохранить пароль в менеджере паролей и получить тестовый access token. Если банк выдаёт отдельный доверенный CA bundle, скачать его с официальной страницы и сохранить рядом с сертификатом. Сроки жизни токенов зависят от [способа выдачи и обновления](https://developers.sber.ru/docs/ru/sber-api/start/connect); перед проверкой убедиться, что токен действителен.
4. До остановки изолированного браузера посмотреть **имя** загруженного файла: `docker exec yandex-isolated ls -1 /home/browser/Downloads`. Скопировать конкретный `.p12` на Mac командой ниже. Команда не выводит содержимое сертификата и создаёт локальную копию с правами `0600` в каталоге `0700`.

   ```bash
   cd sber-assistant
   .venv/bin/python -m assistant.sber_cert_export ИМЯ_ФАЙЛА.p12
   ```

   По умолчанию файл попадёт в `~/.local/share/sber-assistant/secrets/sandbox-client.p12`. Экспорт откажется перезаписывать существующий файл. Браузер не получает доступ к файлам Mac: копирование инициируется с хоста через Docker. Профиль и загрузки браузера находятся в `tmpfs` и исчезнут при пересоздании контейнера.
5. Проверить MCP handshake **без вызова банковских инструментов**:

   ```bash
   cd sber-assistant
   .venv/bin/python -m assistant.sber_sandbox --interactive --service client_info
   ```

   Ввести путь к `.p12`, затем пароль и access token в скрытые терминальные запросы. Если нужен CA bundle, ввести его путь. Успехом считать только ответ `status=connected` с фактическим списком tools от `fintech-test.sberbank.ru`; локальные тесты такого подтверждения не дают. При `status=failed` записать лишь `reason` и время, не публиковать секреты.
6. Сверить возвращённые имена и схемы с локальными двойниками перед любыми `tools/call`. Выделенный read-only probe намеренно не проводит платежи и не меняет банковские данные. Для выступления отмечать отдельно: **локальная симуляция**, **проверенное соединение с песочницей**, **проверенный бизнес-сценарий**.

## Где получить доступ

1. Войти в [СберБизнес](https://sbi.sberbank.ru) и открыть **Все продукты и услуги → Sber API**. [Инструкция личного кабинета](https://developers.sber.ru/docs/ru/sber-api/start/connect) описывает подключение набора «Компаниям», создание сервиса и переход на вкладку **Песочница API**.
2. В настройках песочницы выпустить **клиентский TLS-сертификат `.p12`** и сохранить пароль. Сертификат привязан к `clientId`; для другого сервиса может потребоваться отдельный. См. [требования mTLS](https://developers.sber.ru/docs/ru/sber-api/start/tls).
3. Получить тестовый `access_token` с `MCP_COMMON` и scope выбранного MCP-сервиса. Для первого подключения достаточно `MCP_CLIENT_INFO`. [Требования песочницы](https://developers.sber.ru/docs/ru/sber-api/start/sandbox) указывают сертификат и токен как обязательные параметры.

| Сервис | Дополнительный scope | Официальный адрес песочницы |
|---|---|---|
| Информация о клиенте | `MCP_CLIENT_INFO` | `https://fintech-test.sberbank.ru:9443/fintech/api/client-info/mcp` |
| Выписка | `MCP_STATEMENT` | `https://fintech-test.sberbank.ru:9443/fintech/api/statement/mcp` |
| Платёж | `MCP_PAYMENT` | `https://fintech-test.sberbank.ru:9443/fintech/api/business-payments/mcp` |
| Инкассация | `MCP_ENCASHMENT` | `https://fintech-test.sberbank.ru:9443/fintech/api/encashment/mcp` |
| Депозиты и НСО | `MCP_COMMERCIAL_OFFERS` | `https://fintech-test.sberbank.ru:9443/fintech/api/placement/mcp` |

Адреса закреплены в [документации по клиентским данным](https://developers.sber.ru/docs/ru/sber-api/mcp/mcp-client-info), [выписке](https://developers.sber.ru/docs/ru/sber-api/mcp/mcp-statement), [платежам](https://developers.sber.ru/docs/ru/sber-api/mcp/mcp-payment), [инкассации](https://developers.sber.ru/docs/ru/sber-api/mcp/mcp-encashment) и [размещению средств](https://developers.sber.ru/docs/ru/sber-api/mcp/mcp-placement).

## Проверка соединения

Предпочтительный разовый запуск — `--interactive` из плана выше: пароль и токен не сохраняются в `.env`. Если автоматизация всё же нужна, сохранить параметры как локальные переменные окружения (образец имён — [`.env.sber.example`](../.env.sber.example)), затем из корня проекта запустить:

```bash
.venv/bin/python -m assistant.sber_sandbox --service client_info
```

Команда выполняет только MCP `initialize` и `tools/list`. Она не читает клиентские данные, не вызывает `tools/call` и не создаёт платёж. При успешном ответе печатает `status=connected` и фактические имена tools; при ошибке — только тип ошибки, без токена. Клиент принимает исключительно пять фиксированных тестовых URL; промышленный адрес не задаётся через аргументы.

После первого соединения нужно сравнить фактические `inputSchema` и ответы с нашими упрощёнными локальными двойниками. До такой проверки нельзя считать схемы симулятора совместимыми с Sber API. Нагрузочное тестирование банковской песочницы [не предусмотрено](https://developers.sber.ru/docs/ru/sber-api/start/sandbox); для него остаётся локальный двойник.
